# استقرار BAT-PANEL V2

## وضعیت این نسخه

این نسخه شامل داشبورد فارسی متصل به API، احراز هویت مدیر، ثبت رکوردهای مشتری و نود، heartbeat آزمایشی و منوی مدیریت ترمینال است. هنوز provisioning واقعی VPN، شمارش ترافیک، Agent اجرایی، ربات تلگرام و مهاجرت کاربران V1 تکمیل نشده‌اند. این نسخه را جایگزین production نسخه قدیمی نکنید.

## پیش‌نیاز

- Ubuntu 22.04 یا 24.04، معماری amd64
- دسترسی root و اینترنت
- Docker Engine و Docker Compose plugin
- حداقل 1 GB RAM برای تست سبک
- پورت TCP انتخابی که توسط سرویس دیگری اشغال نشده باشد

## نصب

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/batvin/batpanel/main/install-v2.sh)
```

نصب تازه نام کاربری، رمز عبور حداقل ۱۴ کاراکتری و پورت ۱۰۲۴ تا ۶۵۵۳۵ را می‌پرسد. رمز فقط می‌تواند شامل حروف انگلیسی، عدد و علائم مجاز باشد. اطلاعات ورود در `/root/batman-v2-credentials.txt` با مجوز 600 ذخیره می‌شود.

پنل در `http://SERVER-IP:PORT` در دسترس خواهد بود. اگر UFW فعال باشد، قانون TCP پورت انتخابی اضافه می‌شود؛ فایروال ارائه‌دهنده VPS نیز باید جداگانه تنظیم شود. برای دسترسی عمومی HTTPS را با reverse proxy فعال کنید و پورت را فقط برای IPهای مورد اعتماد باز بگذارید.

## منوی مدیریت

با root:

```bash
bat-panel
```

امکانات منو:
- مشاهده وضعیت و سلامت
- restart، stop و start
- مشاهده لاگ‌ها
- پشتیبان‌گیری دیتابیس
- به‌روزرسانی آخرین کد از GitHub main
- تغییر پورت پنل
- تغییر نام کاربری و رمز مدیر

پیش از update یا تغییرات حساس، دیتابیس V2 در `/var/backups/batman-v2` پشتیبان‌گیری می‌شود. تغییر مشخصات مدیر، رکورد مدیر در دیتابیس و فایل محیطی را به‌روزرسانی و نشست‌های قبلی را نامعتبر می‌کند.

## بررسی سرویس

```bash
docker compose -p batman-v2 -f /opt/batman-v2/docker-compose.yml --env-file /opt/batman-v2/.env ps
curl -fsS http://127.0.0.1:PORT/api/health
```

به‌جای `PORT` پورت انتخابی را قرار دهید.

## مسیرهای مهم

- فایل تنظیمات محرمانه: `/opt/batman-v2/.env`
- اطلاعات ورود: `/root/batman-v2-credentials.txt`
- پشتیبان دیتابیس: `/var/backups/batman-v2`
- منوی ترمینال: `/usr/local/bin/bat-panel`

## حفظ نسخه قدیمی

نصب‌کننده V2 سرویس‌ها و داده‌های نسخه قدیمی را متوقف یا حذف نمی‌کند. حذف کدهای V1 از مخزن GitHub نیز هیچ تغییری روی سرورهای نصب‌شده ایجاد نمی‌کند. پیش از هر مهاجرت، از دیتابیس، گواهی‌ها و فایل‌های VPN بکاپ مستقل بگیرید و مسیر بازگشت را آزمایش کنید.
